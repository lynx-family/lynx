# Lynx `<page>` Element

`<page>` is the root element of every Lynx page. There can be only one `<page>` per page. It can be either implicitly generated by the frontend framework or explicitly authored at the outermost layer of the template.

At the UI layer, `<page>` maps directly to the host native container itself (`LynxView` on Android and iOS). Ordinary elements such as `<view>` are rendered as child views inside the host container, but `<page>` corresponds to the host surface.

## Usage

### Implicit usage (recommended)

By default, you do not need to write `<page>` manually. The frontend framework generates the root automatically. You can still style the root via the `page` or `:root` selectors, or select it via `SelectorQuery:selectRoot()`.

```css
/* Using the page selector */
page {
  background-color: white;
}

/* Using the :root selector */
:root {
  background-color: white;
}
```

### Explicit `<page>`

If you need more control over root styles or events, you can write `<page>` explicitly at the outermost layer. It behaves like `<view>` for most purposes: you can set `style`, `className`, and bind events.

```jsx
<page className="body" bindtap={handlePageClick}>
  <view style={{ width: '100%', height: '100%' }}>
    <text className="title">Page Example</text>
  </view>
</page>
```

**Limitation**: only one `<page>` is allowed per Lynx page.

### Size cannot be controlled via CSS

The size of `<page>` is not controlled by CSS. It is determined by the host native container that embeds the Lynx engine:

- **Android**: the host `LynxView` receives a `MeasureSpec` from its parent Android layout.
  - `UNSPECIFIED` allows the page to expand to fit its internal content.
  - `EXACTLY` or `AT_MOST` fix the page size and content will **not** expand it beyond that bound.
- **iOS**: the host `LynxView` acts as the page surface. Its size is controlled by the host container, not by CSS on `<page>`.
- **Harmony**: the host container acts as the page surface. Its size is controlled by the host container, not by CSS on `<page>`.

This design allows Lynx pages to embed into native client layouts and adapt to the outer container.

## CSS Special Properties

### Root font size (rem baseline)

`page` serves as the `rem` baseline for the entire tree. You can set the root font size via the `page` or `:root` selectors:

```css
page {
  font-size: calc(100vw / 23.4375); /* 1rem = 16px @ 375px */
}
```

When the `page` font size changes, all elements using `rem` units are recalculated.

### Background

Because `<page>` is the root layout node, applying a background covers the full viewport:

```css
page {
  background-color: #f5f5f5;
}
```

## Platform Behavior Notes

- `<page>` exists as the DOM/layout root on Android, iOS, and Harmony.
- Its native backing **is** the host container (`LynxView` on Android and iOS, the host surface on Harmony), not a separate child view created inside the host.
- `<page>` itself is **not** a scroll container. For scrollable long pages, wrap content in an explicit `<scroll-view>` (or another scrolling element) inside `<page>`.

## Common Patterns

### Responsive rem baseline

```css
page {
  font-size: calc(100vw / 23.4375);
}
```

### Scrollable page content

```jsx
<page>
  <scroll-view scroll-orientation="vertical" style={{ height: '100%' }}>
    {/* page content */}
  </scroll-view>
</page>
```

### Select the root via SelectorQuery

```js
lynx.createSelectorQuery().selectRoot().boundingClientRect((res) => {
  console.log(res);
}).exec();
```
